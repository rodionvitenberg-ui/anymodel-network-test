# Сравнение протоколов и обоснование выбора стека

## 1. Матрица кандидатов (состояние на 2026)

| Решение | Транспорт | Устойчивость к ТСПУ | Главный риск |
|---|---|---|---|
| WireGuard | UDP | **Мертва.** Детект handshake-сигнатуры, массовая блокировка с 08.2023 (bbs#274) | Протокол статистически неизменяем |
| AmneziaWG | UDP + обфускация заголовков | Средняя: обфускация маскирует сигнатуру, но UDP-порт-паттерны остаются; требуется клиент-плагин | Гонка вооружений: сигнатуры достраивают под обфускации |
| OpenVPN | TCP/UDP | **Мертва** с 08.2023 (bbs#274) | Детект контрольного канала |
| Shadowsocks-legacy | TCP | **Мертва** с 05.2024 (bbs#363) | Детект по TLS-in-TLS паттерну (≥3 пакета ≥411 B) |
| VMess+WS+TLS | TCP | Низкая: внутренний TLS-хендшейк выдаёт (bbs#363) | Пассивная статистика хендшейка |
| Hysteria2 | QUIC/UDP | Хорошая к DPI-сигнатурам, но: QUIC душится на мобильных сетях РФ; UDP-rate-limit тривиален для ТСПУ | Ставка на UDP, который РКН может отрезать целиком |
| Trojan | TCP+TLS | Низкая: свой сертификат = блокируемый артефакт; TLS-in-TLS | SNI+серт из реестра |
| **VLESS+REALITY+Vision** | **TCP 443, TLS 1.3** | **Лучшая из доступных**: нет собственного сертификата/SNI, ClientHello неотличим от браузерного (uTLS), активные пробы получают сертификат настоящего сайта | IP-репутация, TCP 16-20 freeze на мобильных |

## 2. Выбор: VLESS + REALITY (flow: xtls-rprx-vision)

### Почему это самое живучее решение сегодня

1. **Нечего блокировать по сертификату.** REALITY не имеет собственного сертификата: сервер проксирует TLS-хендшейки неавторизованных клиентов (включая активные пробы DPI) на реальный сайт-«одолжитель» (`dest`). Анализ сертификата даёт сертификат `www.samsung.com`, а не нашего сервера.
2. **Нечего блокировать по SNI.** SNI в ClientHello — легитимный крупный сайт, который ТСПУ блокировать не может без коллатеральных повреждений.
3. **Клиент неотличим от браузера.** uTLS воспроизводит fingerprint Chrome (`fp=chrome`) на уровне ClientHello — против whitelisting TLS-отпечатков (bbs#363, п.2.6 обзора).
4. **Vision ломает TLS-in-TLS эвристику.** Внутренний хендшейк проксируемого HTTPS не образует детектируемый паттерн «3 пакета ≥411 байт» (bbs#363) — это прямое противоядие от майского 2024 метода.
5. **TCP 443 + H2-совместимость**: транспорт, который невозможно отрезать у всей страны, не сломав интернет как таковой.
6. **Матурность**: Xray-core развивается активно (наш клон: v26.10.31), клиенты Hiddify/v2rayNG/Streisand поддерживают VLESS+REALITY из коробки.

### Остаточные уязвимости (честно)

- **IP-репутация**: если ASN VPS в «подозрительном» списке — возможен IP-дроп или TCP 16-20 freeze (bbs#490). Митигация: проверка IP перед покупкой (`whois` ASN, прогон чекеров сообщества), смена IP по факту, запасной сервер.
- **TCP 16-20 freeze на мобильных**: долгий стриминг LLM (>15–20 КБ сервер→клиент в одном соединении) может замерзнуть на затронутых сетях. Митигации: чистый IP; клиентские фрагментаторы (ByeDPI/GoodbyeDPI); запасной транспорт через CDN.
- **Активное развитие ТСПУ**: SNI «одолжителя» может попасть под целевую блокировку → сменить `dest` в конфиге (одна строка + рестарт).
- **Единственный порт/протокол**: нет UDP-фоллбека; если TCP 443 к нашему IP режут целиком — остаётся только смена IP или CDN-транспорт.
- **Поведенческая фильтрация (2025–2026)**: помимо объёмного триггера, ТСПУ на части сетей замораживает трафик при шторме параллельных TLS-рукопожатий к одному IP:443 ([bbs#546](https://github.com/net4people/bbs/issues/546), см. `dpi-overview.md`, п. 2.7). Для боевого профиля (единичные соединения к LLM со стримингом) нехарактерно, но нагрузочный тест 50–200 сессий — ровно такой профиль. Митигация: мультиплексирование (mux/xmux) или транспорт XHTTP (см. план Б).
- **Нет post-quantum**: TLS 1.3 с X25519 — стандарт; квантовая угроза для данной задачи нерелевантна, но упомянуть честно.

### Запасной вариант (план Б, не входит в основной деплой)

VLESS + WebSocket + TLS через Cloudflare CDN (или gRPC): IP принадлежит Cloudflare, блокировка по IP невозможна, но скорость ниже и Cloudflare уже частично блокировали (HRW, март 2025). Требует домена. Конфигурация описана в отчёте как contingency — включается за ~10 минут при деградации основного пути.

**Вариант Б2 — тот же сервер, другой транспорт: VLESS + XHTTP (SplitHTTP) + REALITY.** Отвечает не на объёмный триггер, а на поведенческий анализ: REALITY по-прежнему закрывает рукопожатие и активное зондирование, а после рукопожатия трафик разбивается на обычные HTTP-транзакции (H2/H3) вместо одного долгого TCP-потока — всплески параллельных соединений сглаживаются, к ним добавляется паддинг длины (`xPaddingBytes` в `splithttpSettings`). Транспорт уже присутствует в коде ядра (`transport/internet/splithttp`, включая `xmux`), поэтому включение — это смена `streamSettings` на сервере и в клиентском профиле без смены ядра; перед переводом в бой — прогон `benchmarks/scripts/compat-matrix.sh` на закреплённой версии сервера (26.6.27) и на клиентских ядрах. В деплой не включён осознанно (YAGNI): основной путь работает, а лишний транспорт — лишняя поверхность отказа.

## 3. Серверный профиль

- ОС: Ubuntu 24.04 LTS
- Рантайм: Docker Compose, официальный образ `ghcr.io/xtls/xray-core` с **зафиксированным тегом** версии (без `latest` — воспроизводимость)
- Порт: TCP 443 (только он наружу; Let's Encrypt не нужен — REALITY)
- Секреты: UUID клиента, x25519-пара, shortId — генерируются **на сервере** при установке и не попадают в git

## 4. Клиентский профиль

- Hiddify (Android/iOS/Desktop), v2rayNG (Android), Streisand (iOS) — все поддерживают импорт VLESS-строки и QR.
- Обязательные параметры клиента: `flow=xtls-rprx-vision`, `security=reality`, `fp=chrome`, `sni=<одолжитель>`, `pbk=<серверная публичная часть>`, `sid=<shortId>`.
- **Совместимость**: REALITY-аутентификация ужесточалась в 26.7.x (`minClientVer`) и 26.9.9+ (обязательный key share `X25519MLKEM768`), поэтому требования к клиенту зависят от версии сервера. В проекте версия сервера закреплена на **26.6.27** — на ней работают все клиенты: v2rayNG ≥ 2.3.15, Streisand, `client/install.sh` и Hiddify (sing-box). Детали и матрица версий — `client/README.md`, [`docs/adr/0001-server-pinned-26.6.27.md`](../docs/adr/0001-server-pinned-26.6.27.md).
