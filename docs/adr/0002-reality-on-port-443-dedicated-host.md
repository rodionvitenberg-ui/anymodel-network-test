# REALITY на стандартном порту 443: выделенный VPS вместо общего сервера

Дата: 2026-11-07. Заменяет прежнее решение о нестандартном порте 8443.

Шлюз переехал с общего сервера (`<OLD_SERVER_IP>`: там 443 занят живым nginx с 10+ действующими сайтами — отсюда и был 8443) на выделенный VPS (`<SERVER_IP>`, Ubuntu 26.04, только наши сервисы). На нём 443 свободен, поэтому REALITY слушает стандартный порт. Реальные адреса в репозиторий не коммитятся — см. `report/private-access.md` (gitignored).

- нестандартный порт — единственный оставшийся «запах» туннеля (сам Xray предупреждает про non-443); на 443 сессия неотличима от обычного HTTPS к сайту-одолжителю;
- план Б из прежней схемы на общем сервере (nginx `stream ssl_preread` с переносом всех vhost'ов) больше не нужен: чужого продакшна рядом нет.

## Платформа: контейнер от root

Образ `ghcr.io/xtls/xray-core` штатно идёт под uid 65532. В Docker не-root-процесс не может занять порт <1024 **даже с** `cap_add: NET_BIND_SERVICE` (проверено на 26.6.27: `listen tcp 0.0.0.0:443: bind: permission denied`). Поэтому в `deploy/docker-compose.yml` добавлен `user: "0:0"` — root внутри контейнера нужен ровно для bind 443.

Отклонённые альтернативы:

- `net.ipv4.ip_unprivileged_port_start=0` на хосте — меняет настройки всей машины ради одного контейнера;
- порт 8443 — возвращает non-443;
- NAT-redirect 443→8443 (iptables) — лишний слой и потеря исходных IP в логах.

## Consequences

- `sudo ./scripts/install.sh <IP>` без третьего аргумента разворачивается сразу на 443; третий аргумент (порт) остаётся для случая, когда 443 занят.
- Конфигурация на общем сервере (порт 8443) — история, больше не используется.
- Замеры в `benchmarks/results/` серии 2026-11-05 сняты на 8443 (прежний стенд), серии 2026-11-07 — на 443: порт влияет на заметность, не на скорость. Hiddify/REALITY-совместимость ([ADR 0001](0001-server-pinned-26.6.27.md)) от порта не зависит.
